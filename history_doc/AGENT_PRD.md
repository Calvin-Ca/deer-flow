# 智能体需求文档

> 多智能体系统 —— **深圳市房屋建筑成本预算 Agent（深圳·2013 口径）**
> 文档定位：从工程造价人员的真实请求出发，定义两个核心 Agent（智能组价 / 规范智能问答）的需求边界、意图分类与路由策略。
> **唯一默认作答口径：深圳市房建 + 2013 版计价定额/清单规范**。2024 版为试行版，非默认（见 C-05）。
> 架构基线：三层 Orchestrator–Pipeline–ReAct；检索层不做数值计算；ReAct 用于「特征缺失」「口径缺失（仅规范问答）」「复合」等需澄清或拆解的场景。
> 路由单一事实源：§4.3 决策表为唯一权威路由表，§5 各分类表与附录速查均为其派生视图，改路由只改 §4.3。

---

## 1. 文档目的与范围

### 1.1 目的
本文档梳理工程造价人员在日常工作中可能向智能体发起的请求类型，将其转化为可路由、可验证的功能需求，并明确每类请求落在哪个 Agent、是否越过架构红线、如何兜底。

### 1.2 范围
- **覆盖**：智能组价 Agent、规范智能问答 Agent，以及二者依赖的检索层（ce-code RAG）、计算工具、动态价格取数能力、**规范问答的联网兜底（web_search，仅 FR-K）**。
- **唯一作答口径**：深圳市房建 + 2013 版。组价/价格（FR-P/FR-I）严格锁定此口径；规范问答（FR-K）以此为默认，跨口径走联网兜底（见 C-02/C-05/FR-K07）。
- **不覆盖**：BIM 算量（工程量计算）、清单导出、平台前端交互（仅在涉及 Agent 输入/输出契约时引用）。
- **术语澄清**：本文档只有**两个 Agent**（组价、规范问答）。**计算工具**与**动态价格取数**是被 Agent 调用的*能力/数据源*，不是独立会话主体，不参与 Orchestrator 的意图路由，只在被调用时提供确定性结果。

### 1.3 关键基线（不可协商的硬约束）
| 编号 | 约束 | 说明 |
|------|------|------|
| C-01 | 全量溯源 | 任何规范/定额/价格结论必须附来源（标准号 + **版本/年份** + 条款/子目编号）；缺版本视为溯源不完整。**版本基准为 2013 版**；联网兜底结果须附 URL + 访问日期 |
| C-02 | 地域口径分侧处理 | **组价/价格（FR-P/FR-I）严格锁定深圳口径**，非深圳数据不得进入答案；**规范问答（FR-K）以深圳为默认，本地优先、跨口径走联网兜底（FR-K07）且必须降级标注**。组价侧用户显式要他省口径时见 EH-03 出口 |
| C-03 | 空结果不幻觉 | 库内无命中时不得凭推理补全。规范问答（FR-K）可先走联网兜底（FR-K07）作为拒答前的前置环节；**联网仍无可信命中时仍须明确拒答，不得把"不知道"包装成"有链接的答案"** |
| C-04 | 检索层不算数 | 任何数值计算（量×价、合价汇总、换算）交由计算工具，不在 RAG 层执行 |
| C-05 | 版本固定 2013 | 默认作答口径为 **2013 版**计价定额/清单规范；**2024 版为试行版，非默认**，仅在用户显式指定且（本地有数据 or 联网可查）时带版本标注作答 |

## 2. 工程造价业务全流程（领域背景）

> 本节是**领域背景**，目的只有一个：让开发者看懂两个 Agent 与各能力**嵌在真实造价流程的哪一段**。完整造价从"项目特征"到"总造价"是一条 13 步的成本闭环——本质是 **识别 → 计量 → 定额 → 计价 → 汇总** 的成本闭环。本系统只覆盖其中若干环节，其余（工程量计算、清单导出）由 BIM/平台承担（§1.2 范围）。

### 2.1 全流程 13 步与本系统落点

| # | 阶段 | 核心动作 | 关键产出 | 本系统落点 | 对应 FR |
|:--:|------|----------|----------|------------|---------|
| 1 | 项目特征（输入） | 构件/材料/工艺/施工条件/尺寸 | 结构化特征 | 组价 Agent 的请求载荷（特征槽，见 §4.2 特征完整度） | 输入 |
| 2 | 清单识别与编码 | 按特征匹配《清单计价规范》+地方清单库 | 清单编码/名称/计量单位 | 组价 Agent（清单匹配）+ 规范问答（清单口径） | FR-P / FR-K03 |
| 3 | 工程量确认 | 几何/净量计算、扣减规则 | 清单工程量 Q | **范围外**（BIM 算量，§1.2） | — |
| 4 | 套定额 | 清单项→定额子目，取人材机消耗量 | 单位消耗量（工日/材料/台班） | **组价 Agent 核心**（子目匹配 + 置信度门控 §4.4） | FR-P01/P02/P05 |
| 5 | 材料拆分与标准化 | 定额材料 → 可查价标准材料 | 标准化材料消耗清单 | 组价 Agent（材料标准化/替换） | FR-P04 |
| 6 | 查信息价 | 按地区+时间+规格匹配单价 | 材料/人工/机械单价 | **动态价格取数能力**（C-01/C-02） | FR-I01/I02 |
| 7 | 资源费用（人材机） | 消耗量×单价 | 直接工程费 | **计算工具**（C-04） | FR-X01 |
| 8 | 综合单价 | 直接费+管理费+利润+风险 | 清单项综合单价 | **计算工具**（取费口径由规范问答提供） | FR-X01 / FR-K06 |
| 9 | 分部分项工程费 | 工程量×综合单价 | 主体造价汇总 | **计算工具** | FR-X01 |
| 10 | 措施项目费 | 按定额（脚手架/模板/垂运）/按费率（安文/冬雨季/夜间） | 措施费总额 | 组价 Agent（按定额）+ 规范问答（费率口径）+ 计算工具 | FR-K / FR-P / FR-X01 |
| 11 | 其他项目费 | 暂列/暂估/计日工/总包服务费 | 其他费 | 规范问答（口径）+ 计算工具 | FR-K / FR-X01 |
| 12 | 规费与税金 | 规费（社保/公积金/工伤）、增值税 | 规费、税金 | 规范问答（计税口径）+ 计算工具 | FR-K06 / FR-X01 |
| 13 | 总造价汇总 | 分部分项+措施+其他+规费+税金 | 工程总造价 | **计算工具**（合价汇总） | FR-X01 |

> **读法**：步骤 4 是组价 Agent 的主战场（套定额+置信度门控）；步骤 6 是价格取数能力；步骤 7–9、13 全是纯数值汇总，**一律走计算工具，禁止 RAG 层硬算（C-04）**；步骤 2、8、10–12 的"口径/规则"部分由规范问答 Agent 供给。步骤 3（工程量）是 BIM 上游、本系统范围外。

### 2.2 全流程总图

```
项目特征 → 清单识别(编码) → 工程量计算[范围外] → 套定额(消耗量)
   → 材料标准化 → 查信息价 → 资源费用(人材机) → 综合单价
   → 分部分项费 → 措施费 → 其他费用 → 规费+税金 → 总造价
```

```
落点分布：
  组价 Agent     ▸ 步骤 2/4/5/10（清单匹配·套定额·材料标准化·措施按定额）
  规范问答 Agent ▸ 步骤 2/8/10/11/12（清单·取费·措施·其他·计税 口径）
  价格取数能力   ▸ 步骤 6（信息价/人工/台班）
  计算工具       ▸ 步骤 7/8/9/13（人材机费·综合单价·分部分项·总造价汇总，C-04）
  范围外(BIM)    ▸ 步骤 3（工程量）
```

## 4. 意图分类框架（路由核心）

不按话题（组价/规范/价格）平铺，而是先按**可前置观测的信号**做粗分流，再细分话题——这样才对得上 Orchestrator 的调度逻辑，且每个维度都能在调用 LLM 之前判定。

### 4.0 口径归一（路由前置步骤）

任何请求进四维分流前，先做**口径归一**——确定地域 + 版本：

- **组价/价格（FR-P/FR-I）**：缺地域/版本时**不反问**，直接归一为默认 **深圳·2013**；答案头部声明口径（**会话内首次显示/可折叠，勿每条重复刷屏**）。用户显式要他省口径 → EH-03。
- **规范问答（FR-K）**：缺地域/版本时走 **EH-05 会话粘性反问（B1）**——会话内**首次**问一次"请问您咨询的是哪个地区、哪个版本的规范？"，确认后**会话内记住**，后续同会话不再问；已挂项目上下文（地域已知）时直接沿用、不问。

> 设计依据：组价口径唯一（深圳2013）→ 无歧义 → 不反问；规范问答开了联网兜底（FR-K07）→ 口径成为真有歧义且影响答案对错的变量 → 必须先澄清。会话粘性确保只问一次，避免"每次盘问"拖累常见场景。

### 4.1 四维分流（全部为可前置观测信号）

```
意图路由 = f(来源类型, 项目上下文, 数值计算, 请求形态)
```

| 维度 | 取值 | 如何前置判定 | 路由含义 |
|------|------|--------------|----------|
| 来源类型 | 静态(规范/定额) / 动态(月度价) | 关键词 + 实体识别（钢筋/混凝土+信息价/市场价/本月/近N月 → 动态） | 静态走 RAG 库（**规范问答静态类：本地优先 → 本地 miss 联网兜底 FR-K07**）；动态走价格取数能力 |
| 项目上下文 | 需要 / 不需要 | 请求是否引用"这份清单/本项目/我上传的" | 是否挂载用户当前 BOQ/算量数据 |
| 数值计算 | 需要 / 不需要 | 是否出现量×价、合价、汇总、换算等算子 | 是否触发计算工具（C-04 红线） |
| 请求形态 | 见 §4.2 | 由特征完整度 + 意图数量两个子信号确定 | 是否进 ReAct / 是否先拆解 |

> **设计说明**：原"是否需要多步推理"维度被移除——能否预知"需多步"本身是分类要解决的问题，作为输入会循环定义。改由**请求形态**（§4.2）这一组可观测信号*推出*"是否进 ReAct"，使其成为路由的*结果*而非*前提*。同理新增"来源类型"维度，使动态价格类（§2 步骤 6）有明确归属。

### 4.2 请求形态（驱动 ReAct 与拆解的可观测信号）

| 子信号 | 取值 | 判定方式 | 触发 |
|------|------|----------|------|
| 特征完整度 | 完整 / 缺失 | 组价所需关键特征槽（构件类型、强度等级、断面/规格…，见 §2 步骤 1）的填充率 | 缺失 → ReAct 澄清**特征** |
| 口径完整度（仅 FR-K） | 完整 / 缺失 | 规范问答请求是否含地域+版本（或会话内已确认/项目上下文已知） | 缺失 → **EH-05 会话粘性反问口径**（B1，会话内仅首次） |
| 意图数量 | 单一 / 复合 | 一句话中可拆出的独立子任务数 | 复合 → Orchestrator 先拆解再分路由 |

> **两类「缺失」严格分开**：①特征缺失（构件强度/规格）→ ReAct 只问特征，仅组价；②口径缺失（地域/版本）→ 仅规范问答触发反问，组价侧用默认深圳2013 不问。二者都走 ReAct 通道但问的内容不同。

| 来源类型 | 上下文 | 计算 | 特征 | 意图 | 落点 | 红线 |

### 4.4 置信度门控（组价 Agent 的核心机制，确定性、不调 LLM）

组价直配/ReAct 的分流由检索层后的**确定性门控**决定（对应 §2 步骤 4 套定额），门控只算"匹配分"，不算价（满足 C-04）。

- **置信度 = w₁ · 特征命中覆盖率 + w₂ · 检索相似度**
  - 特征命中覆盖率：清单关键特征在 Top-1 候选子目特征项上的命中比例
  - 检索相似度：Top-1 候选的向量 + BM25 融合得分（归一化）
  - 初始权重建议 w₁=0.6、w₂=0.4，按评测集调参
- **阈值与落点**：
  | 条件 | 落点 |
  |------|------|
  | 置信度 ≥ τ_high（建议 0.85）且关键特征槽无缺失 | 直配，**绕开 LLM**（FR-P01） |
  | τ_low（建议 0.60）≤ 置信度 < τ_high | LLM 辅助确认候选，不直接采信 |
  | 置信度 < τ_low **或** 关键特征槽缺失 | ReAct 澄清（FR-P02 / EH-04） |
- **门控位置**：意图分类与置信度计算均在调 LLM 之前完成；"绕开 LLM"指直配路径不经生成式模型，分类器与门控本身是规则/检索打分，不违反该约束。
- τ_high / τ_low / 权重为可调参数，纳入验收（§8 路由正确率）回归。

| 编号 | 请求类型 | 示例 | 落点 | 约束 |
|------|----------|------|------|------|

| FR-K02 | 清单/定额工程量差异 | 脚手架清单量与定额量为何不一致 | 规范问答（本地优先→FR-K07 兜底） | C-01 |

#### FR-K07 规范问答联网兜底（本地优先 / 三道闸）

**仅 FR-K 开放联网；FR-P 组价、FR-I 价格不开。** 触发链路：本地命中 → 直接答；本地 miss → 联网兜底；联网无可信命中 → C-03 拒答（**拒答须给出路**：说明已查范围 + 建议查阅渠道，不做"死工具")。

**三道闸：**
1. **来源分级，不等同呈现**
   | 层级 | 来源 | 溯源粒度 | 呈现 |
   |---|---|---|---|
   | Tier-1 | 本地权威库（深圳·2013） | 标准号+版本+条款号 | 直接作答 |
   | Tier-2 | 联网检索 | URL+标题+访问日期 | 头部硬标注 `⚠️ 非本系统深圳·2013权威口径，联网检索结果，请人工核验` |
   | Tier-3 | 联网也无可信命中 | — | C-03 拒答（给出路） |
   - **本地命中就不联网**；降级标注**精准克制**，避免"警告失明"。
2. **查询带口径约束 + 结果筛查**

   - 口径外（EH-05 已确认是北京/2024 等）：按问题自身口径查，整段打降级标注。
3. **域名白名单分级**：住建部 / 深圳住建局·造价站 / 省级标准官网 > 行业站 > 博客·文库（最低层或排除）。

对路由最致命的不是话题，而是请求本身的形态。本节定义**形态层**处理策略，与 §5.5 的*业务意图*落点正交：§5.5 回答"拆出来的子任务去哪"，本节回答"如何识别与拆"。

| 编号 | 形态 | 描述 | 处理策略 |
|------|------|------|----------|
| EH-01 | 复合请求 | 一句话含多个意图（套定额 + 算合价 + 合规判断） | §4.2 判为复合 → Orchestrator 拆解为子任务 → 各回 §4.3 路由 → 汇总（FR-X03 等据此执行） |
| EH-02 | 空结果 | 库内无对应项目/材料 | 组价/价格：按 C-03 明确拒答，给"未命中"而非编造；规范问答：先 FR-K07 联网兜底，仍无再拒答。**拒答须给出路**（说明已查范围 + 建议查阅渠道） |

## 7. Agent 与能力职责边界

| 能力 | 智能组价(Agent) | 规范问答(Agent) | 计算工具(能力) | 价格取数(能力) |
|------|:---:|:---:|:---:|:---:|
| 条文/规则检索（本地） | — | ✅ | — | — |
| 联网兜底(web_search) | — | ✅（仅 FR-K07） | — | — |
| 子目匹配 + 置信度门控 | ✅ | — | — | — |
| 数值计算 | 调用 | — | ✅ | — |
| 当期价格/趋势 | 调用 | 调用 | — | ✅ |
| 项目上下文核对 | ✅ | — | — | — |
| 多步推理(ReAct) | ✅（特征澄清） | ✅（EH-05 口径反问） | — | — |

**边界原则**：
- 只有组价、规范问答是参与路由的 Agent；计算工具与价格取数是被调用的*能力*，不独立路由。
- 组价 Agent 是计算工具与价格取数的*调用方*而非*执行方*；规范问答 Agent 永不触碰数值与项目上下文。
- 规范问答 Agent 从「纯检索」升级为「本地检索 + 联网兜底（带工具）」；联网结果一律 Tier-2 降级标注，绝不冒充本系统深圳2013权威口径。
- 组价/价格 Agent **不开联网**，严格锁深圳2013。
- 任何 Agent 在（联网兜底后仍）空结果时一律走 C-03，且拒答给出路。

## 8. 验收要点

### 8.1 功能/红线指标
- **路由正确率**（核心）：以脏请求（EH-01~05）正确分流率为主指标，需配套**带标注的路由评测集**；目标 ≥ 95%。
- **溯源完整率**：FR-K / FR-P 类回答的来源（标准号+版本+条款/子目；联网类 URL+访问日期）附带率 = 100%（C-01）。
- **地域/版本纯净度（分侧）**：组价/价格（FR-P/FR-I）抽样验证无非深圳2013口径泄漏（C-02/C-05 严格）；规范问答（FR-K）口径内答案无 2024/他省杂质混入正文（挡污染闸有效）。
- **联网兜底质量**：本地命中即不联网的命中率；Tier-2 联网答案降级标注覆盖率 = 100%；域名白名单分级正确率；EH-05 会话粘性「仅首次反问」达成率（同会话不重复问）。
- **拒答正确性**：（规范问答经联网兜底后仍）空结果场景的明确拒答率，反向验证无幻觉（C-03）；拒答给出路覆盖率。
- **红线零越界**：检索层数值计算调用次数 = 0（C-04）；组价/价格联网调用次数 = 0。
- **门控有效性**：直配（绕 LLM）路径的准确率与误直配率，用于回归 τ_high/τ_low/权重。

### 8.2 非功能需求（NFR）
- **延迟预算**：纯检索类（FR-K）P95 ≤ 3s；高置信直配（FR-P01）P95 ≤ 2s；ReAct/复合类按交互轮次计，单轮 P95 ≤ 5s。
- **会话状态**：ReAct 澄清（EH-04/FR-P02）为多轮，需维持会话内特征槽与已确认上下文；澄清结果回填后重走 §4.4 门控。
- **多租户隔离**：项目上下文（BOQ/算量）按用户/项目隔离，跨租户不可见；上传与访问需鉴权。
- **可观测**：每次路由落点、置信度、命中来源可审计追溯。
