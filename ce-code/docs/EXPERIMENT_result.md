## 1. 结果口径

- 自动评分来自 `results/eval_v1_20260730/summary.csv`，覆盖全部 386 道题。
- LLM judge 来自 `results/eval_v1_20260730/llm_judge_*.json`，清洗后只有 156/386 道题有有效 judge（40.4%）。
- 清洗规则：去除格式损坏、缺字段记录；同题同模型重复评分按 ID 聚合，overall 取中位数；剔除 judge 理由明确指出“与金标不一致/核心结论错误/无依据”但给 overall=5 的自相矛盾评分。
- 明确发现的一条异常：`eval_sc_ff156194 / group_b` 给出 `1.50×10⁴`，金标为 `1.60×10⁴`，理由承认不一致但评分为5。
- “核心结论正确但条文号错误”的回答保留为部分正确，不作一刀切删除。
- 人工抽检和 Cohen's Kappa 尚未进行，因此以下 judge 结论只用于方向性分析。

## 3. 结果解释

1. `group_d` 的综合领先主要来自条文判断和拒答题。只看正常回答任务时，`group_d=2.543` 与 `group_b=2.506` 基本持平，不能写成 D 的通用问答能力显著领先。
2. `group_b` 在单条文题上最佳，且自动指标显示其输出较短、截断和重复较少，是当前正常问答的效率型候选。
3. `group_c` 在已评计算题上最佳，但全量数值精确率只有5.7%，计算、单位换算和查表仍是共同短板。
4. `group_a` 虽然在当前 judge 跨条文子集上最高，但自动微平均条款 F1仅0.2812，硬幻觉率8.03%，截断率11.92%，重复率18.13%，不宜作为整体候选。
5. `group_d` 的拒答能力最强，但过度拒答代价很大。在人工核验前，应写成“自动规则显示疑似过度拒答”，不能只报告拒答召回率。
6. `base_fewshot` 没有显示 prompt engineering 足以替代训练的证据；其 judge 正常回答均值最低。但由于 judge 覆盖不完整，该结论仍是方向性结论。

## 4. 消融解释边界

- A→B：`group_b` 的自动条款微平均 F1和输出健康度明显好于 `group_a`，但当前 judge 子集并非全量随机样本，不能精确归因于问答转换。
- B→C：`group_c` 的自动宏平均条款 F1略高于 `group_b`（0.5990 vs 0.5904），硬幻觉率略低（0.0181 vs 0.0207），但 judge 正常回答没有稳定领先；质量过滤更像带来小幅可靠性改善，而非整体能力跃升。
- C→D：`group_d` 的跨条文自动 F1最高（0.6470），条文判断 judge 也最高，支持难样本对分项能力有帮助；但拒答边界明显过于保守，不能只用综合分评价 D。

## 5. 可信度与未完成事项

- judge 文件存在拼接数组、自然语言混入、重复评分和覆盖不全问题。
- `review_batches/model_map.json` 对所有题固定 Answer 顺序，尚不能证明实现了逐题随机乱序。
- 重复评分稳定性有限；当前结果不宜用于精确排名或显著性检验。
- 原计划人工抽检100条并计算 Cohen's Kappa，当前暂缓，Kappa 未计算。
- 后续若恢复该步骤，应让两名标注人独立标注同一批 `(题目 ID, 模型)` 单元，先计算人工间 Kappa，再用仲裁标签评估自动规则和 LLM judge 的一致性。
