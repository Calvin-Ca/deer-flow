# 土木工程规范大模型微调与训练数据构造实验报告

实验运行：`eval_v1_20260730`  
评测集：386题（single_clause 115、cross_clause 93、calculation 79、clause_verify 60、refusal 39）  
报告日期：2026-07-31

## 1. 摘要

本项目研究“规范条文 → 指令数据 → 领域大模型微调”的数据构造策略，比较四组训练数据方案：原文模板切分（A）、反向问答生成（B）、质量过滤（C）、跨条文与拒答难样本增强（D）。

实验完成了四组 LoRA adapter 训练、六模型批量推理和自动评分。结果没有完全达到 PRD 预设 KPI，但形成了有区分度的结论：D 组在跨条文和硬幻觉指标上表现最好，同时产生明显过度拒答；C 组的质量过滤只带来小幅可靠性改善；B 组是正常单条文问答中更均衡的候选；数值计算仍是所有模型的共同短板。

## 2. 实验设计

### 2.1 数据与模型

使用 GB50010、GB50011、GB50007、GB50009、JGJ3 五类规范，构建2357条结构化条文库，包含492张表和条款交叉引用信息。评测集由独立出题流程生成，并完成训练集泄漏检查，替换后为0/386超阈值泄漏样本。

模型与训练数据如下：

| 模型 | 训练方式 | 数据构成 | 样本数 |
|---|---|---|---:|
| base | Qwen2.5-7B-Instruct zero-shot | 无训练 | — |
| base_fewshot | 基座 + 3-shot prompt | 无训练 | — |
| group_a | LoRA | 条文原文 × 5模板 | 11770 |
| group_b | LoRA | 2352条文 × 4视角，未过滤 | 9407 |
| group_c | LoRA | B + 可答性/条款准确性/去重过滤 | 4727 |
| group_d | LoRA | C + 跨条文2961 + 拒答1499 | 9187 |

### 2.2 训练控制

四组使用相同基座、LoRA 配置和训练超参数：LoRA `r=32 / alpha=64 / dropout=0.05`，覆盖 attention 与 FFN 投影层；学习率 `1e-4`，bf16，固定 `max_steps=1500`，有效 batch size为16（单卡 `1 × gradient_accumulation 16`），随机种子42。使用 DeepSpeed ZeRO-2 完成训练。

固定 step 而非 epoch，以控制不同数据集大小造成的计算量差异。四组均完成1500步训练，无 OOM/NaN；总训练时长约6小时55分钟。

### 2.3 评测与判分

自动指标包括：

- 条款引用 precision/recall/F1；
- 硬幻觉率（引用不存在条款）；
- 数值精确匹配和数值项命中率；
- 拒答正确率、拒答召回率、误拒率；
- 空答案、截断、重复和平均输出长度。

使用 vLLM 完成6模型 × 386题，共2316条推理。逐题自动判分位于 `results/eval_v1_20260730/metrics/*.jsonl`，合并后的题目、金标和六模型回答位于 `results/eval_v1_20260730/review.md`。

LLM judge 结果经过格式清洗、重复评分按题目/模型取 overall 中位数，并剔除明显自相矛盾的评分；有效覆盖为156/386题（40.4%）。因此 judge 结果只作为方向性证据，不能替代完整人工验证。

## 5. 关键发现

### 5.1 A→B：问答化改善输出工程质量

B组相对A组的条款微F1从0.2812提高到0.6340，平均输出长度从388.8降至100.8 tokens，截断率和重复率也显著降低。由于当前 judge 子集不是完整随机样本，不能将所有差异精确归因于问答转换，但B组明显比原文模板切分更适合作为训练基线。

### 5.2 B→C：质量过滤收益有限但方向正确

C组宏F1为0.5990，高于B组0.5904；硬幻觉率为1.81%，略低于B组2.07%。但C组在judge正常回答任务上没有稳定领先，说明三重过滤当前带来的是小幅可靠性改善，而非整体能力跃升。

### 5.3 C→D：难样本提升了分项能力，但拒答校准失败

D组跨条文自动F1为0.6470，高于C组0.5803，提升6.67个百分点；条文判断 judge 也最高，说明跨条文难样本有效。但D组误拒率达到36.89%，表明拒答样本使模型过度保守。后续应增加“信息足够但表面像不可回答”的困难负样本，优化拒答边界。

### 5.4 Few-shot不能替代领域微调

`base_fewshot` 的条款宏F1略高于base，但微平均F1、硬幻觉率、输出健康度和judge正常回答均值没有形成稳定优势。当前结果支持：领域规范知识注入不能仅依靠少量prompt示例替代。

### 5.5 数值计算仍是共同短板

全量数值精确率最高仅为base的11.4%，B/C/D均约5%～6%。模型经常能够引用相关条文，但在公式选择、单位换算、查表和最终数值上出错。后续需要独立的计算过程训练和确定性校验。

## 7. 局限性与交付状态

- LLM judge 文件存在拼接数组、自然语言混入、重复评分和覆盖不全；当前仅156题有效，不能用于精确排名或显著性检验。
- judge 输出中的 Answer 顺序固定，尚不能证明完成了逐题随机乱序。
- 人工抽检100条和 Cohen's Kappa 暂缓，judge 一致性尚未验证。
- 未进行多随机种子重复实验；小于约1.5个百分点的差异不应解释为显著提升。
- 评测集实际386题而非原始计划400题；自动指标以当前manifest和各题型实际数量为准。
- 规范原文属于内部数据，完整原文不应随代码公开；工作区当前保留合并评审文件、逐题metrics和汇总表。原始 `raw/*.jsonl` 目录被 `.gitignore` 忽略，当前工作区未保留该目录。
