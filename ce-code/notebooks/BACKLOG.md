## `/bill/match` 召回提升（瓶颈已定位：E9）

> **背景（E9，2026-06-18）**：2013 真实 gold（GB-50854-2013，91 条）实测 **Recall@10=56%，40/40 miss 全部在库**
> → 纯检索(嵌入)缺口、非覆盖问题。按 PRD §6 + E4，Top-1 选码归任务层 LLM，知识层目标是**提 Recall@10**。
> miss 一半模板码、一半本体 underspec。详见 [`2026-06-18-1613-casttype-spacefix/`](2026-06-18-1613-casttype-spacefix/) §4-5。

- [ ] **① 模板索引文本增强（最高杠杆，~20 条 miss）**：模板码（0117）名=结构名、不含"模板"二字
  （`011702006`="矩形梁"），被本体拽走召不回。做法：`bill_index` 从 chapter 附录S 的 caption 派生措施类别
  （模板及支架/脚手架/超高/垂直运输…），`bill_embed_text` 在措施项后缀其类别（"矩形梁"→嵌入文本含"模板及支架"）。
  一石二鸟：同解 **E8「本体 vs 模板同名」**（有梁板=010505本体 & 011702014模板）。零新依赖，cast_type 同款机制。
- [ ] **② 本体 underspec（~20 条 miss）**：query 只说"柱/墙"，dense 在含"柱"项里发散（010502 矩形柱只到 rank 9）。
  候选解：(a) query 规范化——"柱"无限定词时补默认"矩形柱"先验；(b) KG/章节约束收窄；
  (c) **BM25 / BGE-M3 sparse 混检**——40/40 在库证明 term 匹配能救召回，**E1「暂不上 sparse」前提（合成 Recall=100%）
  已被真实数据推翻**，sparse 现已 justified。优先复用规范轨已有 rank-bm25（不新部署 BGE-M3）。
- [ ] **③ chapter/caption 脏数据**：MinerU 在中文插空格（"预 制"、"附录 Q 其他装饰"）、子标题当 chapter
  （"H.2 金属门"）→ 污染嵌入文本。嵌入期统一折叠空白 + chapter 归一到附录级。cast_type 已局部去空格（E9），
  此为更广的清洗。
