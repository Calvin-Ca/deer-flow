# 知识层（ce-code）PRD v3

> 知识层 = **数据 + 检索**。把建筑领域知识沉淀为可检索的知识库，对外只暴露检索能力，供上层 agent 调用。
> 本文只回答"要什么、给谁、算不算成功"；**怎么实现（schema / 流水线 / 存储选型 / 检索算法）见 `DEV.md`，进度见 `TODO.md`。**
>
> **v3 变更**：① 修正组价知识来源——首发地区深圳**不使用广东省 2018 定额**，改用深圳市 2024 版消耗量标准（§4，地区强隔离）；② 收录清单对齐 2025 年现行的 2024 版清单计价计算标准，详细收录表移至附件 A（§4）；③ 新增**元数据治理要求**：状态 / 地区 / 效力优先级 / 动态标记，升格为红线（§5、§7）；④ 明确**用户 / 业务层输入边界**——工程量、甲供材、暂估价、询价价格不属知识层（§3）；⑤ 询价"信息价查不到"场景接入"无结果不编"红线（§5）。

---

## 1. 背景与问题

建筑知识问答、智能建造等 agent 需要一个知识底座来提供专业能力。核心诉求是**回答必须可溯源**——具体到条款 / 页码，让用户敢信、能核。通用大模型在建筑规范上既不准、也无出处，无法满足。

> 造价领域还有一层特殊风险：**同一类知识因地区、版本不同而口径不同**（深圳与省内其它城市定额不同；2024 版标准与 2013 版规则不同）。知识层若不做强地区 / 版本隔离，会把不适用的定额、废止的规则召回给业务层，直接导致组价错误。这是本领域区别于通用 RAG 的核心约束。

---

## 2. 目标用户与使用场景

知识层服务于业务层 `ce-services` 的 **CostAgent（算量 + 组价）**，知识层只负责"按需求捞出相关知识"：

| 业务功能 | 使用场景 | 对知识层的期望 |
|---|---|---|
| 算量 | 构件 → 工程量清单（应该算什么 / 如何算） | 返回清单/计量规范候选 + 出处，供业务层选码 |
| 组价 | 清单项 → 人材机含量 + 价格 | 返回定额/价格/费率候选，供业务层在候选内定夺 |

> 业务层只做三件事：① 声明信息需求（intent）；② 把业务对象翻译成查询；③ 设定返回条数。知识层从"查询进 → 结果出"全包。数值计算（几何/扣减/综合单价）由业务层确定性引擎收尾，知识层只在候选内择优。

## 3. 范围边界

### 做什么
- 把建筑规范等知识源整理成**多层次、可溯源**的知识库。
- 对外暴露统一的检索能力，业务层以纯客户端方式复用。
- 对检索质量（召回 / 排序）负责。
- 对返回知识的**地区适用性、版本时效性**负责（带状态与地区元数据，废止 / 不适用的不召回）。

### 不做什么（划归业务层 `ce-services`）
- 答案生成、对话、多 agent 编排。
- 算量引擎（几何 + 扣减）、综合单价计算、Excel 导出、施工图解析。
- 人工确认（HITL）流程。
- **端到端任务指标的拥有**（答案正确率 / 编码 Top-1 / 组价准确率）——这些归业务层。

### 不属知识层的输入（用户 / 业务层提供，非知识）
> 以下是**项目特有事实**，无法从规范 / 数据推导，知识层不持有、不生成：

| 输入 | 谁提供 | 说明 |
|---|---|---|
| 工程量（数量） | 用户 | 本阶段绕开算量引擎，由用户给已确认的量 |
| 甲供材清单及供货价 | 用户 | 业主与施工方合同约定，系统无从推导 |
| 暂估价及暂估单价 | 用户 | 投标商务决策，系统不替定 |
| 询价材料市场价 | 用户 / 询价源 | 信息价查不到的材料价格（见 §5 红线 3） |

### 与业务层的职责接缝
- 业务层：选 intent + 翻译查询 + 设返回数；只有它懂业务对象语义。
- 知识层：知识表示 + 检索策略，对召回负责；**检索策略不下放**（否则各 agent 各搓一套、互相漂移、无法统一优化）。

## 4. 知识收录范围

知识层是**算量组价的造价知识底座**，按"算量"与"组价"两个环节所需的知识组织。数据源不止 PDF：定额是消耗量标准，价格是定期更新的信息价，历史库是项目沉淀。

> **首发范围：深圳市 · 房屋建筑专业。** 跑通后再扩地区 / 专业。
> **地区强隔离（硬约束）**：深圳项目**只用深圳本地标准**，**绝不能召回广东省 2018 定额**——深圳有独立的 2024 版消耗量标准，这是深圳与省内其它城市最大的差异，也是最易串库的坑。
> **版本现状**：国家 2024 版清单计价计算标准 2025-09-01 起实施（GB 50500-2013 同时废止）；深圳本地 2024 版配套规则 2026-01-01 起执行。过渡期项目可能仍按旧标准，故收录单元须带"状态 / 实施日期"以供过滤。

### 算量所需（应该算什么 / 如何算）
| 知识 | 作用 | 来源 / 编号 |
|---|---|---|
| 建设工程工程量清单计价标准 | 应该算什么（清单编码、报价格式） | 国标 GB/T 50500-2024 |
| 房屋建筑与装饰工程工程量计算标准 | 如何算（工程量计算规则） | 国标 GB/T 50854-2024 |
| 通用安装工程工程量计算标准 | 房建含水电安装时的计量规则 | 国标 GB/T 50856-2024 |

### 组价所需（人材机 + 价格 + 费率 + 税费）
| 知识 | 作用 | 来源（深圳房建现行） |
|---|---|---|
| **深圳市建筑工程消耗量标准（2024）** | 每个子目的人、料、机消耗量（组价主体） | 深圳市住建局（**替代省定额**） |
| 深圳市土石方与地基基础工程消耗量标准（2024） | 土方 / 地基阶段消耗量 | 深圳市住建局 |
| 深圳市装配式建筑工程消耗量标准（2024） | 装配式专项（按项目） | 深圳市住建局 |
| 深圳市建设工程施工机械台班消耗量标准（2024） | 机械台班单价依据 | 深圳市住建局 |
| 深圳市建设工程计价费率标准（2023） | 企业管理费、利润、安全文明施工费、规费、税金费率 | 深圳市造价管理站 |
| 深圳市 2024 版清单计价标准落地配套规则及附件 | 本地计价规则、总包服务费 / 甲供扣减等规则 | 深圳市住建局 |
| 建设工程安全文明施工标准 SJG 46-2023 | 安全文明施工做法（与费率配套） | 深圳市住建局 |
| **材料价格信息（深圳市价格信息月刊）** | 定额只规定消耗量、不规定价格，需价格库补 | 深圳市造价管理站（**动态，月更**） |
| 税费依据 | 增值税税率及附加 | 国家税务政策、财政部文件 |
| 历史工程库 | 已完成项目的量价特征（脱敏），供相似案例对标 | 内部沉淀 |

> 详细收录清单（含文号、实施日期、效力优先级、入库优先级、动态标记）见**附件 A：深圳房建规范收录表**。

### 收录单元的元数据治理（强一致、可审计）
每个收录单元须携带，并作为检索过滤依据：

| 元数据 | 作用 |
|---|---|
| 版本 / 标准编号 | 区分 2024 版与历史版本 |
| 状态（现行 / 废止 / 待执行） | **仅"现行"参与召回**；废止单元不召回 |
| 适用地区 | 支撑地区强隔离（深圳 ≠ 省内其它城市） |
| 适用专业 | 房建专业过滤 |
| 实施 / 废止日期 | 支撑过渡期项目按时点选标准 |
| **效力优先级（1~4）** | 口径冲突时排序取值：深圳本地 = 1（最高） → 国标 = 4（最低，越具体越优先） |
| 是否动态 + 更新频率 | 信息价（月更）走独立更新管道，与静态规范分离 |

## 5. 核心原则（产品红线）

1. **可溯源是底线，不可妥协**。任何返回的知识单元都必须能回指到原始出处（具体条款 / 页码 / 定额子目），支撑"出处可查、PDF 高亮定位、人工核对"。任何检索优化都不得牺牲可溯源。
2. **多层次还原**。清单/计量规范自带目录结构，知识库须按其原生层级还原（而非打散成无结构片段），深度自适应——保住"条 → 款"的从属关系与交叉引用。
3. **无结果不能编**。检索不到就如实返回空 / 降级，绝不杜撰条款或价格。**典型场景：材料在信息价中查不到时，返回空并让业务层触发询价待办，绝不编造单价。**
4. **能算的不交给模型猜**。清单↔定额是多对多关系，需检索 + 关系约束协同收窄候选，LLM 只在候选内择优；数值由业务层确定性公式收尾。
5. **地区 / 版本不串库**。检索结果必须符合查询声明的地区与时点：不召回他地区定额，不召回废止 / 未生效的规则。隔离失败等同于召回错误。

## 6. 验收标准

### 红线（必须满足）
- **可溯源**：每条返回内容具体到条款或页码。
- **无结果不编**：无命中时返回空或父级范围，不杜撰。
- **地区 / 版本正确**：返回单元的地区、状态与查询声明一致，无跨地区 / 废止单元混入。
- **测试集达标**：在评测集上检索质量达标（口径见下）。

### 核心指标（= 知识层成功指标，不跑业务层即可测）
- **召回率（Recall@k）为首要指标**——金标（清单编码 / 定额子目 / 条款）是否出现在返回的前 k 条内（k 取业务实际消费值）。
- **清单候选集命中率**——构件对应的正确清单项是否在候选内。
- **定额套用准确率**——清单项 → 定额的关系是否正确。
- **地区 / 版本隔离准确率**——返回单元中跨地区或废止单元的混入率，目标趋零。
- 指标须带**排序敏感度**（Recall@k / MRR / 金标秩），避免"金标排第 95 位也算召回"。

### 指标归属与归因
- 知识层只对**检索质量**负责；**端到端任务指标（答案正确率 / 编码 Top-1 / 组价准确率）归业务层**。
- 端到端失败时按"金标是否在返回 top-k 内"归因：**否 → 知识层**（漏召 / 排序过低 / 地区版本串库）；**是 → 业务层**（生成 / 编排）。
- 评测金标由业务层参与定义（"做成我的任务，你必须捞出这些清单/定额"）。

### 业务层端到端红线（知识层需支撑，非自身指标）
- 编码匹配 Top-1 ≥ 85%、组价准确率达标；红线内只建议不定稿，必须经人工确认（HITL 在业务层）。
- 知识层的清单候选集命中率、定额套用准确率须高到足以支撑业务层达成上述红线。

## 7. MVP 与验证

> 验证"规范这一层够不够用、组价逻辑对不对"，应绕开图纸解析与算量（最高风险环节），用最小闭环测知识层。

**最小收录集（先跑通纯土建房建一条清单）**：
1. GB/T 50500-2024（清单总则）
2. GB/T 50854-2024（房建工程量计算）
3. 深圳市建筑工程消耗量标准（定额主体）
4. 深圳市建设工程计价费率标准（2023）（取费）
5. 深圳市价格信息最新一期（信息价）

**最小验证用例**：给一段**已知工程量的清单项**，验证知识层能否正确捞出：① 对应清单编码与计量规则（国标）；② 深圳消耗量子目（本地定额，非省定额）；③ 当期信息价；④ 适用费率。命中且地区 / 版本无串库 = 知识层这层验收通过。
