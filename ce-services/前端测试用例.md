# 前端对话框测试用例 —— 智能问答（norm-qa）+ 智能组价（cost-agent）

> 用途：在前端对话框逐条复制「**输入**」粘贴测试两个子 agent，对照「**期望行为**」核验。
> 重点验编排层从没在服务器跑过的两件事：**多轮反问（ask_clarification）** 与 **HITL 红线**。
> 用例里的构件描述/金标编码均取自 `ce-code/data/eval_set/match_gold*.jsonl`（真实评测集），不是杜撰。

## 前置（四服务必须在跑，否则 agent 调 skill 会拿连接错误）

| 服务 | 端口 | 起法 |
|---|---|---|
| vLLM Qwen3-8B（agent 基座 + 生成 + 选码） | 8099 | 须已在跑 |
| 知识服务（/search /bill/match /price/compose） | 8100 | `cd ce-code && uv run python -m service.knowledge_api` |
| 任务服务（/norm/qa /cost/compose） | 8101 | `cd ce-services && uv run python main.py` |
| Gateway + 前端 | 8001 | debugpy 起 Gateway + 前端页面 |

可用规范/版本：
- **norm-qa standard**：`gb50500-2013/2024`（清单计价）、`gb50854-2013/2024`（房建计量）、`gb50856-2024`（安装计量）
- **cost-agent spec**：`2024` 组价数据已就绪；`2013` 仅选码、**组价数据未就绪**（应降级提示）

## 一、智能问答 norm-qa

### A1 多轮反问 —— 不给版本（核心验证点）
- **输入**：`满堂脚手架工程量怎么计算？`
- **期望**：**先 ask_clarification 反问**查哪部/哪版规范（房建/安装？2013/2024？），**不替你猜默认**。
- **第二轮回**：`gb50854-2024`
- **期望**：检索条文 → 带引用作答（cited_clauses 只引检索到的，附免责声明）。

### A2 多轮反问 —— 计量规则类
- **输入**：`矩形柱按什么规则计量？`
- **第二轮**：`gb50854-2024`
- **期望**：反问→检索→引用作答。⚠️**已知瓶颈**：现浇柱计量规则困在 chunk 的 `tables` 字段、未进检索文本，此问可能召回到装饰柱/钢柱而非现浇柱规则——若答非所问，是**知识层召回缺口**（见 `ce-code/TODO.md` 四），非 agent 编排问题。

### A3 直接检索 —— 一次性给全（不该再反问）
- **输入**：`按 gb50500-2024 综合单价包含哪些费用？`
- **期望**：standard 已明确，**不再反问**，直接检索作答；若零召回应明说"未检索到相关条文"，**不编条文**。

### A4 零召回边界 —— 验不编造
- **输入**：`按 gb50856-2024 通风管道的防火阀怎么计量？`
- **期望**：cited_clauses 为空时如实说"未在该规范检索到相关条文",建议换规范/换问法，**绝不自己编条文号**。

### A5 跨版本对比 —— 验版本红线意识
- **输入**：`房建计量规范 2013 和 2024 在墙面抹灰计量上有什么区别？`
- **期望**：识别到涉及两版,要么分别检索两版条文对照,要么提示需逐版查询;**不把两版混引到同一条**。

### A6 越界提问 —— 验不超纲
- **输入**：`按 gb50016 防火分区最大允许建筑面积是多少？`
- **期望**：gb50016 不在已建索引规范内,应明确告知不支持该规范(只支持 50500/50854/50856 造价类),**不强答**。

## 二、智能组价 cost-agent

### B1 多轮反问 —— 不给版本（核心验证点）
- **输入**：`C30现浇混凝土矩形柱怎么组价？`
- **期望**：**先 ask_clarification 反问按 2013 还是 2024 国标**,绝不猜默认。
- **第二轮**：`2024`
- **期望**：选码（金标 `010502006` 现浇钢筋混凝土柱）→ 取定额工料机含量 + 信息价单价；明确声明"不含综合单价/含税造价,不算钱"。

### B2 描述不足反问 —— 验补全关键特征
- **输入**：`这个柱子套什么清单码？`
- **期望**：描述不足(缺混凝土等级/现浇预制),**先反问补全**关键特征,再调脚本。

### B3 正常选码 + 组价（2024 直通）
- **输入**：`按 2024 国标给"MU10标准砖240厚实心砖墙M5水泥砂浆"组价`
- **期望**：spec 已明确,直接选码(金标 `010401002` 实心砖墙)+ 组价;need_review=false 时给出 code + reason + price。

### B4 已知召回缺口 —— 验 HITL 不当定稿（重点）
- **输入**：`按 2024 国标给"C30现浇混凝土矩形梁"组价`
- **期望**：金标 `010502011` **未进 top-10**（库里"钢筋混凝土梁"名实不符,见 `ce-code/TODO.md` 三）。LLM 可能在无正解的候选里**高置信选错码**——验 agent 是否如实透传 `need_review` / 不把可疑结果当定稿。这是端到端 Top-1 卡 80% 的主因,属**知识层召回缺口**,不是 agent bug。

### B5 现浇/预制消歧 —— 验不被字面诱选预制码
- **输入**：`按 2024 国标给"门窗洞口上C25现浇混凝土过梁"组价`
- **期望**：选**现浇**过梁 `010502023`,**不**因字面"过梁"误选预制过梁 `010503006`（prompt 已补现浇/预制消歧,验是否生效）。

### B6 钢筋 vs 本体 —— 验选码细粒度
- **输入**：`按 2024 国标给"现浇混凝土柱内HRB400钢筋制作安装"组价`
- **期望**：选**柱钢筋** `010506002`(按 t 计),区别于柱本体 `010502006`(按 m³);验是否混淆本体与钢筋。

### B7 2013 版本降级 —— 验组价数据未就绪
- **输入**：`按 2013 国标给"实心砖墙"组价`
- **期望**：2013 **能选码但组价数据未就绪**,应明确说"该版本组价数据未就绪,只有选码"(price_status=未就绪),**不杜撰价格**。

### B8 造码防御 —— 验只在候选内选码
- **输入**：`按 2024 国标给"某种我自定义的新型复合保温墙体"组价`
- **期望**：库内无对应清单时,**不自己编 9 位码**;选码只接受候选内编码,无合适候选→转人工(need_review/code=null),如实告知"需人工复核编码"。

### B9 一次性给全 —— 验不该再问执行确认
- **输入**：`按 2024 国标,深圳,给"加气混凝土砌块墙200厚专用砂浆砌筑"组价`
- **期望**：spec + 描述 + 地区都全,**直接执行**,不再就"是否执行"二次确认;选码 `010402001` 砌块墙 + 组价。

## 三、HITL 可中断组价验证（三入口，建议按 ①→②→③ 顺序）

> 上面「二」验的是 cost-agent **一次性 compose**（选码+取数、不算钱）。HITL 是**可中断完整组价**（编码→定额→
> 信息价→费率→参数→总造价复核，逐闸停下来等人确认/录入，最后出总造价）。同一套图有三个入口，前置不同。

### ① curl 无头（最易，仅需 :8099/:8100/:8101）

最干净地验图本身。服务器从 `ce-services` 根逐条单行执行：

```
TID=$(curl -s -X POST localhost:8101/cost/session/start -H "Content-Type: application/json" -d '{"feature":"C30现浇矩形柱","spec":"2024","region":"深圳"}' | tee /tmp/hitl.json | python3 -c "import json,sys;print(json.load(sys.stdin)['task_id'])"); echo $TID
```
看停在哪个闸：`python3 -c "import json;d=json.load(open('/tmp/hitl.json'));i=d.get('interrupt') or {};print(d['status'],i.get('gate_type'),i.get('node'))"`，再逐闸 resume（决策体见 SKILL.md / 下面 ③ 模板）：
```
curl -s -X POST localhost:8101/cost/session/$TID/resume -H "Content-Type: application/json" -d '{"decision":{"action":"manual_override","value":"010503001"}}' > /tmp/hitl.json
```
**验收**：编码→定额→缺价→费率→参数→总造价 review→`status=done`，`rollup.total` 有数；终态 `audit`/`override` 链全。
**顺带验**：编码闸 `evidence.source_ref` 是精确串（无 `TODO(knowledge-layer)`）；选码结果含 `external_confidence`（路 2 校准生效，非恒 0.95）。

### ② 前端专门页面 `/workspace/cost`（需前端重启/重建）

前置：`:8099/:8100/:8101` + **前端拉代码后重启(dev)/重建(prod)**（新增路由）。登录 → 侧栏「智能组价」→ 填
`C30现浇矩形柱 / 2024 / 深圳` → 开始 → 逐闸点（confirm 看依据卡 + 备选；input 按字段录；review 看明细）→ 右侧依据时间线。
**不依赖 agent**，最干净地验控件本身。出错看浏览器 Network 里 `/api/cost/session/*` 响应 + ce-services 日志。

### ③ 对话框驱动（cost-agent skill + 内嵌交互控件，最接近"对话组价"，前置最多）

前置（四样全齐）：`:8099/:8100/:8101` + **cost-agent skill 已加载**（`extensions_config.json` enabled）+ **cost-agent agent 已注册**（`config.yaml` `subagents.custom_agents.cost-agent`）+ **前端拉新代码并重启/重建**（内嵌控件是新代码）。
> skill 改了：`git pull` 后 `skills/public/` 即生效，但 SKILL.md 注入 system_prompt，**gateway 需重启 / `touch extensions_config.json` 刷缓存**才读到新 playbook。

**机制（Tier 2，已做成 Claude Code 那种内嵌卡片）**：agent **只起会话**（`cost.py start`）并把输出的 ```cost-hitl marker
**原样贴进回复**；前端识别 marker → **在对话气泡内嵌渲染交互式组价控件**（confirm/input/review + 依据卡，复用
`/workspace/cost` 那套），用户在控件里逐闸点选/录入，控件直接打 `/api/cost/session/*` 驱动会话——**闸交互全程不经 agent**
（红线复位：弱模型不当编排器）。agent 基座是不是 Qwen3-8B 此时**影响很小**（它只需可靠地起会话 + 贴一个代码块）。

#### H1 对话驱动完整组价（核心验证点）
- **输入**：`帮我把 C30 现浇矩形柱按 2024 国标走完整组价，算到总造价`
- **期望**：agent 反问/确认版本(若没给) → `cost.py start` → **回复里出现内嵌「智能组价 · HITL」卡片**（不是纯文字问句）。
- **在卡片里逐闸操作**（点选/录入，非打字）：编码确认（看依据卡 + 备选）→ 定额确认 → 缺价逐条录入 → 费率（管理10/利润5/风险0/取费基数 labor_machine）→ 参数（措施/规费/税率）→ 总造价复核「通过」。
- **期望终态**：卡片显示 `已完成` + 总造价；全程同一会话（卡片绑定一个 task_id）。

#### H2 marker 必须原样贴（控件能否出现的命门）
- **观察**：agent 回复里应**有 ```cost-hitl 代码块**（前端据此渲染控件）。若 agent 把它改写成 JSON 描述/表格/翻译，则**控件不出现**、退化成纯文字——属 agent 没遵守"原样贴"（SKILL 使用原则 3）。

#### H3 费率不替填默认（红线 4，控件侧保障）
- **场景**：在费率闸卡片里**留空取费基数**直接提交
- **期望**：控件**必填校验拦住**（提交按钮禁用 / 标红），不会带空值/默认值过闸——结构化控件天然守住红线，不靠弱模型自觉。

#### H4 纯命令行兜底（无前端时，可选）
- 无前端控件的环境（curl/API），见 §三①：`start` 拿 task_id → `resume` 逐闸。决策体见 SKILL「备用」节。

## 四、判读速查（出问题往哪归因）

| 现象 | 大概率根因 | 归属 |
|---|---|---|
| agent 不反问、直接瞎答 / 不调 bash 脚本 | Qwen3-8B function-calling 不稳（config.yaml 12-13 行已标注） | **agent 编排层**（调 prompt 或切回 qwen-plus 基座） |
| 主对话不把问题分发给子 agent | 子 agent 路由/委派未触发 | **agent 编排层**（确认主 agent 委派或 UI 选中子 agent） |
| 答非所问 / 召回到错构件（如 A2、B4） | 检索召回缺口（表体未注入 / 名实不符） | **知识层 ce-code**（sparse 混检 / 表体注入待修） |
| 提示"无法连接服务"/502/503/400 | :8099/:8100/:8101 某个没起 | **服务端配置**（按前置表逐个起 + 看 /tmp 日志） |
| 选码进了候选却选错（如矩形梁高置信错码） | 候选内 LLM 选码 + 置信度全 0.95 无区分度 | **任务层**（扩 gold + 治本置信度；路 2 校准已落地，待调参） |
| HITL 对话（③）回复是纯文字、不出内嵌控件 | agent 没把 ```cost-hitl marker 原样贴出来（改写/翻译了） | **agent 编排层**（SKILL 使用原则 3；或基座换 qwen-plus 提稳） |
| HITL 对话（③）控件出来但点了无反应/报错 | 前端代理 `/api/cost/*` 打不到 :8101 / get_state 无 interrupt | **服务端**（:8101 起没起 + 拉新 ce-services 代码；看 Network `/api/cost/session/*`） |
| HITL 对话（③）agent 没读到新 playbook | SKILL.md 注入 system_prompt 的缓存未刷 | **服务端**（重启 gateway / `touch extensions_config.json`） |
| 前端（②/③）控件/侧栏不出现 / 404 | 前端没拉新代码或没重启/重建 | **前端**（dev 重启 / prod rebuild） |
