Agent · Skill · Tool 装配

造价智能体 · 运行单元 / Skill / 工具的装配架构

按 deer-flow 的设定：一个运行单元（lead agent 或 sub-agent）装配若干 skill， skill 又通过 allowed-tools 从全局工具池裁出可见子集； 此外运行单元还能用 config 的 tools / disallowed_tools 直接白/黑名单裁剪。 本图按仓库实际配置绘制，MCP 工具逐一列名。

⑤ 装配铁律

代码强制，非文档约定

工具全局、不归 agent 私有

MCP tool 全局注册一次；每个运行单元只拿 skill(allowed-tools) ∩ config(tools) 裁出的受限视图。

两条裁剪通道取交集

无 skill 声明 allowed-tools → 不裁剪；本项目 sub-agent 走 config tools 白名单，skill 通道留给 lead 侧全量。

弱模型不驱动流程

能力路由确定性；HITL 是否停闸由服务端图决定，agent 只呈现闸 + 收集决策 + resume。

LLM 不算钱

综合单价 / 总造价 = 确定性公式 + pydantic 闸门；计算函数不作 MCP 前门，只在 workflow 内部。

宁缺毋造

选码只在候选内 · 零召回拒答 · 缺价 no_source 透传 · 低置信 need_review 转人工。

同名不同物

cost-agent/norm-qa 既是 sub-agent 名也是 skill 名——sub-agent 由 config 定义、skill 由 SKILL.md 定义，勿混淆。
