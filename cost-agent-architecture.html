造价智能体系统数据流架构图

这张图以“用户消息”为输入，展示消息在系统内部的真实流向： 先进入 lead_agent，再根据意图分流到子智能体或完整组价 workflow； 子智能体通过 skill 获得受限工具视图；所有 MCP 工具位于系统全局工具池； 完整组价通过 session API 和 workflow 管状态、HITL、重入和审计。

智能体装配与可见工具集
运行单元 声明来源 Skill 可见工具集如何派生 边界
lead_agent 系统默认入口智能体 cost-agent, norm-qa 内置工具 + skill 过滤后的全局 MCP 工具；必须能看到 task、ask_clarification 和 session 入口。 对话入口、任务分配、启动 workflow、解释最终结果。
norm_qa_agent config.yaml / subagents.custom_agents norm-qa norm-qa/SKILL.md 的 allowed-tools 允许 ask_clarification、ce-rag_search_clause、ce-rag_get_clause。 只做规范知识问答。
bill_match_agent config.yaml / subagents.custom_agents bill-match bill-match/SKILL.md 的 allowed-tools 允许 ask_clarification 和 ce-rag_match_bill_item。 只做候选内清单码选择。
quota_agent config.yaml / subagents.custom_agents quota-match quota-match/SKILL.md 的 allowed-tools 允许 ce-db_quota_get 和 ce-db_quota_list。 只做定额查询和候选选择。
cost_workflow ce-services/cost/session.py + ce-services/cost/graph.py 无 服务端内部调用模块和无状态工具，不受智能体 skill 过滤影响。 完整组价状态机、HITL、持久化、重入、审计。
全局工具池暴露策略
全局工具类别 注册位置 对智能体的暴露方式
规范问答 ce-rag_search_clause, ce-rag_get_clause, ce-rag_expand_clause_refs 暴露给 norm_qa_agent，必要时也可暴露给 lead_agent。
清单匹配 ce-rag_match_bill_item 暴露给 bill_match_agent，通常不直接暴露给 lead_agent。
定额匹配 ce-db_quota_get, ce-db_quota_list 暴露给 quota_agent；workflow 可在服务端内部使用等价函数。
询价与计算 ce-db_price_query, ce-db_price_compose, 内部计算函数 询价可按 skill 暴露给智能体；计算主要给 workflow 内部使用。
完整组价 Session 不建议作为长期 MCP tool 通过应用层 Session API 暴露：start、state、resume、revise。

架构规则

工具是全局的，智能体不拥有工具。每个智能体通过自己装配的 skill 获得全局工具池的受限视图。 单点判断交给子智能体；完整组价交给有状态 workflow；HITL 是 workflow 的中断协议，不是一个智能体。
