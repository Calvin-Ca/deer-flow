## 1. 背景与假设

- **问题**：E6/E7 发现 2013 措施项（0117）成片全灭，根因经 grep 定性为**标准错配**——之前 2013 轨建库用的是
  `GB_50500_2013_建设工程工程量清单计价规范`（计价规范），其措施项目编码体系与 gold 不同：50500 里
  `011702006`=满堂脚手架，而 gold（真实房建项目）用的是 **GB 50854-2013（房建计量规范）**，那里
  `011702006`=矩形梁（模板）。同码不同义 → 措施桶无法评。
- **修正**：服务器用 MinerU 重新解析了**正确源 GB 50854-2013**（房屋建筑与装饰工程工程量计算规范），已切 chunks。
  本地核验：附录S 措施项目 `011702006`=矩形梁、`011702002`=矩形柱（模板），**与 gold note 完全对齐**。
- **假设**：换成 GB 50854-2013 建库后，措施桶（0117）能正常命中，整体 Top-1/Recall 显著提升；本体桶（010xxx，
  两标准编码一致）保持或更好。

关键逐条：
- ✅ **措施模板码语义修复（核心成效）**：`板模板`→`011702014 有梁板`(模板) **Top-1**；`梁模板`→gold
  `011702006 矩形梁`(模板)进 **top-10 rank 3~4**；自定义体脚手架→`011701006 满堂脚手架` **Top-1**。
  E7 里这些因"满堂脚手架"错义全灭，换对源后能召回。
- 🐛 **柱本体仍全 miss**：`柱；混凝土强度C40` gold `010502001 矩形柱`(现浇) 被 `010509001 矩形柱`(预制) 压。
  **根因**：`010509001` caption = `"预 制混凝土柱"`（MinerU 把"预制"插了空格），`cast_type` 的 `"预制" in cap`
  子串匹配漏判 → 预制未被 down-rank。**确定性 bug，去空格归一即修。**`010502001` 已确认在库（name=矩形柱、
  cap=现浇混凝土柱）。
- 🆕 **本体 vs 模板同名**：`有梁板`=`010505001`(本体,附录E) 又=`011702014`(模板,附录S)；矩形梁/柱同理。模板码
  **名里不含"模板"** → `STRUCTURAL_MARKERS` 抓不到，致 `梁模板 011702006` 输给 `有梁板模板 011702014`。

## 5. 分析与结论

- **对照**：换源**解开了措施项"同码不同义"死结**（E6/E7 的最大黑洞）——模板码现在语义正确、能召回，这是本实验
  的核心目标，达成。聚合指标看似没涨，是因 gold 换了集（不可直比）+ 两个新暴露的可修问题压住了上限。
- **分桶**：钢筋/后浇带/回填本体桶仍稳 Top-1（零回归）；措施模板桶从"全灭"变"部分命中"（板模板 Top-1、梁模板
  top-10）；柱本体桶被 cast_type 空格 bug 拖死；本体/模板同名是新的次级混淆。
- **结论 ✅（换源成功，但需两个跟进修复才能见数字）**：正确源是对的，措施语义已通；Top-1 上不去是
  cast_type 空格 bug + 本体/模板同名两个**确定性问题**，非检索能力问题。

  3. chapter/caption 脏（MinerU 空格）→ 嵌入期统一折叠空白（更广的清洗，单列）。
