# PRD — 土木工程规范大模型微调与数据构造策略研究

## 1. 背景与问题

通用大模型在土木工程规范问答上存在两个致命问题：

1. **幻觉条款号**——会编造形似真实的条款编号（如"GB50010 第 12.4.7 条"），而该条并不存在。土木领域答错规范的后果是工程事故，这是不可接受的可靠性红线。
2. **无法多跳推理**——真实工程问题往往需要同时引用 2 条以上规范（如轴压比限值 + 箍筋加密要求分属不同条款）。

同时，与医疗、法律不同，**土木领域不存在任何公开的指令微调数据集**，只有规范条文本身。因此本项目的核心不是"数据筛选"，而是**"数据合成策略"**。

## 2. 项目目标

**主目标**：通过四级递进的数据合成消融实验，量化回答三个问题：

- Q1：把条文转换成问答形式，能带来多大提升？（A → B）
- Q2：对合成数据做质量过滤，价值主要体现在哪个维度？（B → C）
- Q3：补充难样本（跨条文、拒答），对复杂查询和幻觉抑制的作用有多大？（C → D）

**次目标**：产出一套可迁移到其他垂直领域的"无监督语料 → 高质量指令数据"方法论，及配套的自动化质检与评测工具链。

## 3. 非目标（明确不做，防止范围蔓延）

- ❌ 不做全参数微调（数据量与算力都不支持，且非本项目研究对象）
- ❌ 不做推理部署优化（量化、吞吐、并发）
- ❌ 不做 RAG（本项目研究的是参数化知识注入，RAG 是另一条路线，可在报告的"局限与展望"中讨论）
- ❌ 不做多模态（规范里的图表暂以文字描述替代）
- ❌ 不追求 SOTA，不与商用模型比绝对分数
- ❌ 不做前端界面

## 5. 指标定义（验收标准）

> 所有指标的实现必须与本节定义逐字对应。修改定义需同步更新本节并重跑全部评测。

### 5.1 条款引用 F1（全自动，客观）

- **抽取**：正则从模型输出中提取所有条款号，经归一化（去空格、统一"GB50010-2010"格式、中文简称映射）后成集合 `pred`
- **对照**：评测集 `gold_clauses` 字段成集合 `gold`
- **计算**：`P = |pred ∩ gold| / |pred|`，`R = |pred ∩ gold| / |gold|`，取 F1
- **为何用 F1**：防止模型罗列大量条款号刷召回

### 5.2 硬幻觉率（全自动，客观）— 本项目核心指标

- **定义**：`pred` 中存在于条文库之外的条款号，即模型凭空捏造
- **计算**：出现至少一个捏造条款号的题目数 / 400
- **口径**：以题为单位，不以条款号为单位

### 5.3 软幻觉率（半自动）

- **定义**：条款号真实存在，但模型陈述的内容与该条原文不符
- **检测**：从模型输出中抽取与该条款绑定的关键数值/关键词，与条文库中该条原文比对；比对不上的送 LLM judge 二次确认
- **说明**：此指标噪声较大，报告中作为辅助指标呈现

### 5.4 拒答表现（半自动）— 必须成对报告

|  | 模型拒答 | 模型硬答 |
|---|---|---|
| 该拒答（40 题） | 正确 | **过度自信**（危险） |
| 不该拒（360 题） | **过度保守**（无用） | 正确 |

- **拒答正确率** = 该拒答且拒答了 / 40
- **误拒率** = 不该拒却拒答了 / 360
- **禁止只报前者**（全部拒答可得 100%）
- 拒答判定：关键词规则打底（"建议咨询""需结合具体""规范未直接规定"等），规则不确定的样本人工过一遍

### 5.5 分题型准确率（三层漏斗判分）

| 层 | 方式 | 覆盖 |
|---|---|---|
| 1 | 关键数值精确匹配（正则抽数值+单位，与 `gold_values` 比对） | 目标 ≥60% 的题 |
| 2 | LLM judge（盲评，输出 正确/部分正确/错误） | 剩余描述性题目 |
| 3 | 人工抽检 100 条（五个模型各 20 条），算 Cohen's Kappa | 验证第 2 层可信度 |

**LLM judge 必须做的防偏差处理**：
- 不告知 judge 输出来自哪个模型
- 同题多模型答案随机打乱顺序
- prompt 中不引导长度偏好

### 5.6 训练效率

记录各组训练时长、峰值显存、总 token 数，用于成本-效果权衡讨论。

## 6. 目标值（用于判断实验是否成功）

| 指标 | 目标 | 说明 |
|---|---|---|
| 条款引用 F1 | group_c ≥ 0.85 | 若 C ≈ B，说明质量过滤无效，需回头检查过滤器 |
| 硬幻觉率 | group_d ≤ 0.08 | 核心卖点，必须达成 |
| 跨条文准确率 | group_d ≥ 0.60，且 D − C ≥ 15pt | 若提升不显著，说明难样本构造方式有问题 |
| 拒答正确率 | group_d ≥ 0.70，同时误拒率 ≤ 0.10 | 成对约束 |
| judge 一致性 | Kappa ≥ 0.75 | 低于此值则 LLM judge 结果不可用，需扩大人工评测 |

> **重要**：以上是预期，不是必须达成的 KPI。若实验结果与预期相反（例如质量过滤没有带来提升），**这同样是有价值的结论**，如实记录并分析原因，不要为了好看的数字反复调参。

## 7. 交付物

1. 五个模型在 400 题评测集上的完整推理输出与判分明细（`results/`）
2. 分题型指标对比表（5 行 × 7 列）
3. 实验报告 `reports/report.md`：含实验设计、结果表、关键发现、局限性
4. 可复现的代码仓库 + 一键复现脚本
5. 脱敏后的评测集（可开源，作为项目亮点）
