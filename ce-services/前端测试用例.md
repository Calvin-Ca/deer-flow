# 前端对话框测试用例 —— 智能问答（norm-qa）+ 智能组价（cost-agent）

> 用途：在前端对话框逐条复制「**输入**」粘贴测试两个子 agent，对照「**期望行为**」核验。
> 重点验编排层从没在服务器跑过的两件事：**多轮反问（ask_clarification）** 与 **HITL 红线**。
> 用例里的构件描述/金标编码均取自 `ce-code/data/eval_set/match_gold*.jsonl`（真实评测集），不是杜撰。

## 前置（四服务必须在跑，否则 agent 调 skill 会拿连接错误）

| 服务 | 端口 | 起法 |
|---|---|---|
| vLLM Qwen3-8B（agent 基座 + 生成 + 选码） | 8099 | 须已在跑 |
| 知识服务（/search /bill/match /price/compose） | 8100 | `cd ce-code && uv run python -m service.knowledge_api` |
| 任务服务（/norm/qa /cost/compose） | 8101 | `cd ce-services && uv run python main.py` |
| Gateway + 前端 | 8001 | debugpy 起 Gateway + 前端页面 |

可用规范/版本：
- **norm-qa standard**：`gb50500-2013/2024`（清单计价）、`gb50854-2013/2024`（房建计量）、`gb50856-2024`（安装计量）
- **cost-agent spec**：`2024` 组价数据已就绪；`2013` 仅选码、**组价数据未就绪**（应降级提示）

## 一、智能问答 norm-qa

### A1 多轮反问 —— 不给版本（核心验证点）
- **输入**：`满堂脚手架工程量怎么计算？`
- **期望**：**先 ask_clarification 反问**查哪部/哪版规范（房建/安装？2013/2024？），**不替你猜默认**。
- **第二轮回**：`gb50854-2024`
- **期望**：检索条文 → 带引用作答（cited_clauses 只引检索到的，附免责声明）。

### A2 多轮反问 —— 计量规则类
- **输入**：`矩形柱按什么规则计量？`
- **第二轮**：`gb50854-2024`
- **期望**：反问→检索→引用作答。⚠️**已知瓶颈**：现浇柱计量规则困在 chunk 的 `tables` 字段、未进检索文本，此问可能召回到装饰柱/钢柱而非现浇柱规则——若答非所问，是**知识层召回缺口**（见 `ce-code/TODO.md` 四），非 agent 编排问题。

### A3 直接检索 —— 一次性给全（不该再反问）
- **输入**：`按 gb50500-2024 综合单价包含哪些费用？`
- **期望**：standard 已明确，**不再反问**，直接检索作答；若零召回应明说"未检索到相关条文"，**不编条文**。

### A4 零召回边界 —— 验不编造
- **输入**：`按 gb50856-2024 通风管道的防火阀怎么计量？`
- **期望**：cited_clauses 为空时如实说"未在该规范检索到相关条文",建议换规范/换问法，**绝不自己编条文号**。

### A5 跨版本对比 —— 验版本红线意识
- **输入**：`房建计量规范 2013 和 2024 在墙面抹灰计量上有什么区别？`
- **期望**：识别到涉及两版,要么分别检索两版条文对照,要么提示需逐版查询;**不把两版混引到同一条**。

### A6 越界提问 —— 验不超纲
- **输入**：`按 gb50016 防火分区最大允许建筑面积是多少？`
- **期望**：gb50016 不在已建索引规范内,应明确告知不支持该规范(只支持 50500/50854/50856 造价类),**不强答**。

## 二、智能组价 cost-agent

### B1 多轮反问 —— 不给版本（核心验证点）
- **输入**：`C30现浇混凝土矩形柱怎么组价？`
- **期望**：**先 ask_clarification 反问按 2013 还是 2024 国标**,绝不猜默认。
- **第二轮**：`2024`
- **期望**：选码（金标 `010502006` 现浇钢筋混凝土柱）→ 取定额工料机含量 + 信息价单价；明确声明"不含综合单价/含税造价,不算钱"。

### B2 描述不足反问 —— 验补全关键特征
- **输入**：`这个柱子套什么清单码？`
- **期望**：描述不足(缺混凝土等级/现浇预制),**先反问补全**关键特征,再调脚本。

### B3 正常选码 + 组价（2024 直通）
- **输入**：`按 2024 国标给"MU10标准砖240厚实心砖墙M5水泥砂浆"组价`
- **期望**：spec 已明确,直接选码(金标 `010401002` 实心砖墙)+ 组价;need_review=false 时给出 code + reason + price。

### B4 已知召回缺口 —— 验 HITL 不当定稿（重点）
- **输入**：`按 2024 国标给"C30现浇混凝土矩形梁"组价`
- **期望**：金标 `010502011` **未进 top-10**（库里"钢筋混凝土梁"名实不符,见 `ce-code/TODO.md` 三）。LLM 可能在无正解的候选里**高置信选错码**——验 agent 是否如实透传 `need_review` / 不把可疑结果当定稿。这是端到端 Top-1 卡 80% 的主因,属**知识层召回缺口**,不是 agent bug。

### B5 现浇/预制消歧 —— 验不被字面诱选预制码
- **输入**：`按 2024 国标给"门窗洞口上C25现浇混凝土过梁"组价`
- **期望**：选**现浇**过梁 `010502023`,**不**因字面"过梁"误选预制过梁 `010503006`（prompt 已补现浇/预制消歧,验是否生效）。

### B6 钢筋 vs 本体 —— 验选码细粒度
- **输入**：`按 2024 国标给"现浇混凝土柱内HRB400钢筋制作安装"组价`
- **期望**：选**柱钢筋** `010506002`(按 t 计),区别于柱本体 `010502006`(按 m³);验是否混淆本体与钢筋。

### B7 2013 版本降级 —— 验组价数据未就绪
- **输入**：`按 2013 国标给"实心砖墙"组价`
- **期望**：2013 **能选码但组价数据未就绪**,应明确说"该版本组价数据未就绪,只有选码"(price_status=未就绪),**不杜撰价格**。

### B8 造码防御 —— 验只在候选内选码
- **输入**：`按 2024 国标给"某种我自定义的新型复合保温墙体"组价`
- **期望**：库内无对应清单时,**不自己编 9 位码**;选码只接受候选内编码,无合适候选→转人工(need_review/code=null),如实告知"需人工复核编码"。

### B9 一次性给全 —— 验不该再问执行确认
- **输入**：`按 2024 国标,深圳,给"加气混凝土砌块墙200厚专用砂浆砌筑"组价`
- **期望**：spec + 描述 + 地区都全,**直接执行**,不再就"是否执行"二次确认;选码 `010402001` 砌块墙 + 组价。

## 三、判读速查（出问题往哪归因）

| 现象 | 大概率根因 | 归属 |
|---|---|---|
| agent 不反问、直接瞎答 / 不调 bash 脚本 | Qwen3-8B function-calling 不稳（config.yaml 12-13 行已标注） | **agent 编排层**（调 prompt 或切回 qwen-plus 基座） |
| 主对话不把问题分发给子 agent | 子 agent 路由/委派未触发 | **agent 编排层**（确认主 agent 委派或 UI 选中子 agent） |
| 答非所问 / 召回到错构件（如 A2、B4） | 检索召回缺口（表体未注入 / 名实不符） | **知识层 ce-code**（sparse 混检 / 表体注入待修） |
| 提示"无法连接服务"/502/503/400 | :8099/:8100/:8101 某个没起 | **服务端配置**（按前置表逐个起 + 看 /tmp 日志） |
| 选码进了候选却选错（如矩形梁高置信错码） | 候选内 LLM 选码 + 置信度全 0.95 无区分度 | **任务层**（扩 gold + 治本置信度） |
