# ce-code 实验体系

> 知识层造价轨的**实验记录规范**。每一次实验性尝试（建库/检索/抽取/评测的改进）都独立成一个
> **按工作时间命名的文件夹**，完整留下「背景 / 配置 + 运行脚本 / 结果 / 分析」四件，便于复现与回溯。

---

## 1. 工作流（服务器跑 → 本地分析）

设备分工见仓库根 `CLAUDE.md`：本地（Mac）写代码 + 写实验设计 + 事后分析；服务器（GPU）实际跑。
一次实验的生命周期：

1. **本地（开跑前）**：建实验文件夹，写 `README.md` 的「背景/假设 + 配置 + 变量」段，写 `run.sh`
   （服务器要跑的单行命令），commit & push。
2. **服务器（跑）**：`git pull` → `bash notebooks/<文件夹>/run.sh 2>&1 | tee notebooks/<文件夹>/results/run.log`
   （结果重定向进 `results/`），把产出 commit & push。
3. **本地（跑后）**：`git pull` 取回 `results/`，补全 `README.md` 的「结果 + 分析 + 结论 + 下一步」段，
   commit & push。

> 结果文件（eval 指标表 / 日志）**入 git**（派生小文本，跨机同步分析必需）；大体积索引/向量仍不入 git。

## 2. 文件夹命名

```
notebooks/<YYYY-MM-DD-HHMM>-<短描述>/
```

- 前缀 `YYYY-MM-DD-HHMM` = **工作时间**（开跑或设计时间），保证目录天然按时间排序。
- 短描述用 kebab-case 点题（如 `prefab-disambig`、`bill-match-baseline`），方便肉眼找。
- 取时间：本地 `date "+%Y-%m-%d-%H%M"`。

## 3. 文件夹内容

| 文件 | 内容 | 何时写 |
|---|---|---|
| `README.md` | 背景/假设 · 配置 · 运行脚本说明 · 结果 · 分析 · 结论 · 下一步（见 `_template/README.md`） | 开跑前写前半，跑后补后半 |
| `run.sh` | 服务器实际跑的命令（**单行、无 `\` 续行**，见 `CLAUDE.md` 约定；每条独立一行） | 开跑前 |
| `results/` | 服务器产出：`run.log`（命令输出 tee）、指标表截图/文本、必要的中间样本 | 服务器跑后 |

照 `_template/` 起新实验：`cp -r notebooks/_template notebooks/<YYYY-MM-DD-HHMM>-<短描述>`。

## 4. 结论速查 timeline

`experiments.md` 是**精炼结论时间线**（E1、E2… 一条一行结论，重负结果），作快速回溯索引；
**详细过程**（完整配置/脚本/逐条结果/分析）落各 dated 文件夹。新实验：
- 在对应 dated 文件夹写全过程；
- 在 `experiments.md` 顶部加一条精炼结论（标 `✅采纳 / ⛔负结果 / 🟡待续`），并链到文件夹。

## 5. 原则

- **一次只动一个变量**：每个实验聚焦单一改动（换模型 / 加一个重排规则 / 换数据源），对照基线测，
  否则归因不清。配置段明确写「本次相对上一个实验只动了什么」。
- **留负结果**：走不通的路 + 为什么，比成功更值钱（避免后续盲目重试）。
- **真实数字**：结果段贴**实际跑出的数**（指标 + 关键逐条样本），不写"大概提升了"。
- **可复现**：`run.sh` + commit 号让任何人能在服务器重跑同一实验。
