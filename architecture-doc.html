§1 背景、目标与约束

1.1 用户与起点场景

目标用户是造价员。真实起点：手头有项目实体名称 + 项目特征描述（设计说明），需要完成 「列清单 → 套定额 → 综合单价 → 汇总费用」的计价链条。系统的价值不在复现计价软件已做好的算术，而在 解决传统计价软件难解决的判断类问题：

判断类难题（本系统主攻）传统软件现状本质
特征描述 → 清单编码（语义选码）人工翻规范、凭记忆语义匹配
整份设计说明 → 清单草表（列清单/列项）逐条手工建抽取＋规划
清单项 → 套哪些定额（组合规划）靠老师傅经验组合判断
描述缺什么关键特征、该反问什么软件不会问知识驱动澄清
BOQ 漏项 / 错套 / 合理性核对人工复核探索式对照
规范条文问答（计量/计价规则）翻书检索＋引用生成

算术段（综合单价、取费、报表）是计价软件的主场：本系统只做内部验证 + 可导出，不做用户向打磨。

§3 核心模式：Workflow 编排 Agents（倒置的 supervisor）

常见 multi-agent 是「supervisor agent 在顶指挥 workers」——在审计域 + 弱模型下不可复现、不可审计、指挥官本身最不可靠。 本架构倒置：确定性 workflow 在顶拥有控制流，agent 只在开放式子任务节点内部自治。并行、上下文隔离等 multi-agent 收益全保留，失败被局部化，审计天然成立。

3.1 主打场景管线：设计说明 → 清单-定额建议表（批量，规划中）

顶层 Workflow（确定性代码，非模型） │ ├─ ① 解析 [清单生成 Agent]agent 迭代读设计说明 · 调 bill_match · 自查遗漏 │ ↓ 信封：items[]（逐项 provenance + confidence） ├─ ② 门控 代码判定确定 高置信直过 / 低置信标黄待审 —— 不弹对话，进评审表标注 ├─ ③ 组价 并行 fan-out：每件一个 [组价 Agent]agent × N（独立上下文） │ 内部：选码 → 组合套定额 → 取数 ↓ 每件一个提案信封 ├─ ④ 复核 [Critic Agent]agent 对抗式审查：漏项？错套？组合合理？ → 质疑清单 ├─ ⑤ 评审 评审表 HITL人 造价员像审 diff 一样一遍过（批量确认，不逐件弹闸） ├─ ⑥ 算钱 确定性原语确定 unit_price / rollup（政策数由录入闸收，零 LLM） └─ ⑦ 导出 Excel / 计价软件格式确定 造价员在既有软件完成交付

交互范式变化：从「逐闸对话串行确认」→「批处理＋集中评审表」。门控逻辑完全复用（τ 阈值、多候选、缺价），只是呈现从"暂停对话"变为"表格标注"。现有单构件 HITL 图保留为精查路径。

任务性质机制本系统实例

Agent 数量不是设计目标，「知道哪里不用 agent」才是。本系统预计仅 3~4 个节点值得 agent 化，其余保持窄点与纯函数。

§4 关键机制设计

机制设计要点状态
意图路由两级混合：确定性 prerouter（关键词/信号，强信号零延迟直配，金标可回归）→ 低置信才升 32b 兜底分类（temp=0、enum、代码校验、fail-safe 跌回）。LLM 只出能力标签；出界/口径/特征/形态四个红线闸两条路都确定性重推。补：out_of_domain 第五标签＋顶层直答✅、「列清单/列项」词条＋金标✅（2026-07-04 落地，47+8+12 自测、30/30 金标全绿；32b 兜底服务器实测 17/17=100%、P95 639ms，提示词反例锚点修复口语误判后收口）；余 prior_capability 会话粘性入参。已建，余一项
第零跳收权RouteContextMiddleware（deer-flow 中间件，照抄 DynamicContextMiddleware 模式）：每轮消息先调 /route，RouteDecision 以 system-reminder 注入；模型从「自由分诊」降为「按判定执行」；:8101 不可达则不注入（fail-open）。路由单一源留在 ce-services，harness 只做消费者。已灰度实证（07-05）：天气句 cap=out_of_domain/llm_fallback→8B 不再编造预报、正确声明能力范围；列清单句注入前后行为质变（空跑 compose→先 ask_clarification 问特征）；组价句 deterministic 直配+如实透传 501。踩坑修复：前端消息 content 为块列表致首版静默早退——fail-open 路径必须出声（可观测性教训）。已灰度
HITL 门控门控不逐步 gate：τ 双阈值三段式（≥τ_high 直配 / 中段人工确认 / <τ_low 提示补描述）＋多候选/缺价/缺政策数才停；末尾 review 恒停。compute/gate 双拆——interrupt resume 从节点头重跑，昂贵 LLM 调用放上游有 checkpoint 的 compute 节点。用户决策 lock_value 钉死，下游确定性重算不重跑 LLM。已建
Provenance来源是字段不是散文：每个数字带 {source_type, source_ref, confidence, alternatives}；前端只从结构化字段渲染，不解析模型自然语言。audit_log + overrides 支撑交付对账。待知识层补文件+行号级 source_ref。已建，粒度待补
模型分桶桶 A Qwen3-8B（延迟敏感：生成/澄清/皮肤）；桶 B 32B（真推理：选码消歧/拆解综合/意图兜底）；URL+model 成对回落防半错配。置信校准：8b 自报置信无区分度 → cosine 客观分校准、只拉低不抬高。未来强模型可入桶 C 供 agent 原语用。已建
契约单一源信封/闸 payload/路由判定升级为 pydantic model → OpenAPI/JSON Schema → TS 类型代码生成（openapi-typescript），替换三处手抄镜像；CI 做 schema diff。规划（现为手抄）
HITL 握手结构化通道替代 marker：task_id 从工具结果（tool-result）通道取，前端不再用正则从模型正文抠 fenced block——消除最脆接缝。规划（现为 marker）

  • 端到端金标：若干真实项目「说明→总价」对账（后段算钱作为验证工具的价值兑现）
  • 文档定版：本文档随实现更新，PRD 范围修订（批量主线入 PRD，算钱段降级为验证+导出）
验收：全部金标进 CI，任何 PR 破线即红；一页对比报告（确定性 / 单 agent / 多 agent × 三指标）。

§8 红线与风险

不可协商红线

1数值与编码只来自工具返回：不杜撰——缺价 no_source、缺政策数停闸、无映射诚实 blocked，绝不虚构总价
2是否停闸问人、路由红线（出界/口径）永远确定性，任何模型不碰
3LLM/agent 不算钱：算术全在 pydantic 闸的纯函数里
4agent 只出提案：钉值权在闸和人；用户确认 = 权威锁定，不再重跑模型
5每个模型触点必有确定性降级，且成对回落（URL+model）

主要风险与对策

知识层数据完整度
（2013 组价未就绪、source_ref 粒度粗）		如实 501/标注，不静默换版本；M4 端到端对账倒逼补数;判断质量优先于编排打磨
弱模型驱动 agent 不稳agent 原语从抽取式 v0 起步；planner 类角色用 32b/API;入籍守则强制降级路径
复杂度税（图/闸/契约四处联动）契约单一源＋代码生成；agent 化克制（3~4 节点）;评审表复用门控不新造逻辑
诚实的 UX 代价（政策数全要人填）项目级默认值/记忆上次输入/批量录入;评审表批处理替代逐闸串行

一句话收束：这套架构对「agent」的回答不是拥抱或拒绝，而是分层问责——workflow 拥有骨架与钱，agent 贡献判断与提案，皮肤只负责把这一切说成人话。模型每变强一档，被收编的疆域可以扩大一格；但骨架、闸门与账本，永远在代码手里。
